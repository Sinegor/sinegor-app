# Интеграционный E2E-контур

Одна команда поднимает копию текущих исходников, отдельную PostgreSQL с двумя БД и ролями, FastAPI, Strapi и собранный SSR frontend. Playwright обращается к ним через общий origin. HTTP API приложений, авторизация, CSRF, PDF-хранилище и транзакции работают без подмены.

## Подготовка

Нужны POSIX-система (проверено на Linux), Python 3.12, Node.js 22.12–26, Docker с доступом к daemon, свободные loopback-порты и место для сборок. Зависимости устанавливаются по существующим lock-файлам. Из корня репозитория:

```bash
cd apps/api
uv sync --locked
cd ../web
npm ci
npx playwright install chromium
cd ../cms
npm ci
cd ../..
docker pull postgres:16
```

На Linux для Chromium могут потребоваться системные библиотеки, указанные установщиком Playwright. Runner не устанавливает зависимости и не скачивает Docker image. Рабочие `.env`, SMTP-пароли, токены Диска и Telegram для него не нужны.

## Запуск

Из корня:

```bash
apps/api/.venv/bin/python tests/e2e/run.py
```

Выбор одного сценария и каталога результатов:

```bash
apps/api/.venv/bin/python tests/e2e/run.py --suite workflow --output /tmp/sinegor-e2e-workflow-results
```

`--suite`: `all` (по умолчанию), `workflow`, `cms`, `notifications`, `resilience`. `--output` должен указывать на новый или пустой каталог. Каждый запуск создаёт окружение заново, включая запуск одного сценария. Из `apps/cms` команда `npm run test:integration` запускает этот же runner с `--suite cms`.

## Покрытие и границы

| Сценарий | Что проверяется совместно |
|---|---|
| `workflow.spec.cjs` | TOTP, приглашение и Magic Link, заказ, обмен и утверждение разных PDF, права/IDOR, ручная оплата, папка и передача материалов, отказ и повтор SMTP, граница 14 дней через настоящий CLI, независимая отсрочка, явное подтверждение и асинхронное удаление, сохранность подписанного PDF и журнала, выход |
| `cms.spec.cjs` | Черновик/публикация/изменение/снятие с публикации в Strapi, SSR без пересборки и JavaScript, SEO/экранирование, медиа и запрет публичной записи |
| `notifications.spec.cjs` | Консультация через UI, сбой Telegram, сохранение задания, повтор настоящим CLI и очистка контактных полей |
| `resilience.spec.cjs` | Остановка процесса CMS, контролируемый SSR 503, доступность FastAPI и восстановление CMS |

SMTP, Telegram и Яндекс Диск заменены **только на внешней границе** локальными протокольными fixtures: SMTP TLS/AUTH, HTTPS с проверкой сертификата, ответы API и ошибки. Тестовый launcher FastAPI и CLI направляет домены провайдеров на loopback и блокирует прочие внешние соединения. Используются синтетические адреса `example.org`, пустые PDF и тестовые ресурсы. Это проверка настоящих адаптеров, но не реальной доставки писем, доступности облака или ручной выдачи прав в интерфейсе Яндекса.

Тестовые команды `data.py` создают администратора/пустые PDF, сдвигают даты и время повтора заданий только в БД данного запуска; сам жизненный цикл выполняют HTTP API и штатные CLI. CMS fixture использует Document/Upload services настоящей Strapi. Новых административных маршрутов в приложениях нет.

Подробные матрицы бизнес-правил и конкуренции остаются в [pytest](../../apps/api/tests/README.md). Проверки интерфейса с перехватом API остаются в `apps/web/tests/browser/` (`npm run test:e2e` из `apps/web`). Новый контур сохраняет четыре значимых сквозных сценария из [отчёта T1](../../docs/reports/t1-2026-10-23/README.md); прежний CMS smoke использует один общий сценарий.

## Изоляция и завершение

- Снимок не включает Git, dotenv, локальное хранилище соглашений, CMS uploads и старые отчёты. Установленные `node_modules` используются через ссылки; сборки выполняются в снимке.
- Секреты генерируются на запуск. Переменные с рабочими реквизитами, `PYTHONPATH`, `NODE_OPTIONS` и proxy-настройки родительской оболочки не наследуются приложениями.
- PostgreSQL создаётся в отдельном контейнере `sinegor-e2e-<run_id>` с label `sinegor.e2e.run=<run_id>`, временной файловой системой и случайным портом на `127.0.0.1`. Существующие Compose-контейнеры и тома не используются.
- После успеха, ошибки, SIGINT или SIGTERM runner останавливает собственные группы процессов, удаляет свой контейнер после проверки label и приватный временный каталог. SIGKILL или отключение питания обработать невозможно.

В `run.json` остаются идентификатор запуска, итог и признак `cleanup`; в `results.json` — имена, статусы, длительности и очищенные ошибки Playwright. Traces, скриншоты, видео, письма, cookie, токены и PDF не сохраняются. Приватные сырые журналы удаляются вместе с окружением; ранняя ошибка подготовки содержит только безопасное описание этапа/типа ошибки.

Ненулевой код выхода означает ошибку теста, подготовки или очистки. Сначала проверьте `run.json`, наличие зависимостей, Docker image и доступ к loopback. При `cleanup: false` или аварийном завершении сверяйте имя и label контейнера с `run.json` перед ручным удалением; проверьте оставшиеся процессы и принадлежащий запуску `/tmp/sinegor-e2e-private-*`. Не удаляйте контейнеры по одному лишь общему префиксу. Остатки приватного каталога могут содержать тестовые секреты.

## Проверки самого контура

Из корня:

```bash
apps/api/.venv/bin/python -m unittest discover -s tests/e2e -p 'test_*.py' -v
node tests/e2e/reporter.test.cjs
apps/api/.venv/bin/ruff check --config apps/api/pyproject.toml tests/e2e
apps/api/.venv/bin/ruff format --config apps/api/pyproject.toml --check tests/e2e
apps/web/node_modules/.bin/prettier --check 'tests/e2e/*.cjs' apps/cms/tests/smoke.js
```
