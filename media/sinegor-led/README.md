# SINEGOR LAB — LED-надпись для Blender 5.1.1

Пользователь выбрал вариант свечения **B**. Финальный экспорт завершён в Blender
**5.1.1** и сохранён отдельно в `output/final_B/`: 2048 × 720, 25 FPS, PNG RGBA 8 бит,
50 кадров включения и 750 кадров цикла, пульсация ореола ±4%.
Все 800 PNG проверены; два цикла проверены вне GUI через установленный движок
Shotcut/MLT. Сводка — `output/final_B/FINAL_REPORT.md`.
Файлы не затрагивают функциональность web/backend/CMS, исходное видео и проект Shotcut.

## Выбранный вариант B

- `output/final_B/intro/intro_0001.png` … `intro_0050.png` — включение, 2 секунды.
- `output/final_B/loop/loop_0001.png` … `loop_0750.png` — цикл, 30 секунд.
- `output/final_B/SINEGOR_LAB.blend` — две редактируемые сцены, шрифт упакован.

- `output/final_B/png_sha256.json` — SHA-256 каждого PNG после проверки.

Параметры B: `glow_near_px=26`, `glow_near_opacity=0.90`, `glow_far_px=90`,
`glow_far_opacity=0.50`, `glow_intensity=1.0`, `loop_amplitude=0.04`.
`config.json` сохраняет исходные параметры. `glow_presets.json` содержит исходный,
A/B/C; пресеты меняют только свечение. Обоснование и сравнение при 683 × 239 —
`output/glow_revision/REPORT.md` и `output/glow_revision/comparison_683x239.png`.
Подложка в сравнении — имитация `#171C20`, не реальная табличка.

## Запуск

Используйте **Blender 5.1.1**, а не системный Python для `generate.py`.
Встроенного Python Blender достаточно; дополнительных пакетов и сети не нужно.
Скрипт очищает текущую сцену, поэтому запускайте его в отдельном процессе.

Из корня репозитория на Linux:

```bash
# Пробные кадры выбранного B, в отдельной папке glow_revision/B:
media/sinegor-led/run_blender.sh --mode preview --preset B

# Исходный вариант: сохранить две сцены; ничего не рендерить:
media/sinegor-led/run_blender.sh --mode build

# Сохранить сцены и отрендерить только восемь тестовых PNG:
media/sinegor-led/run_blender.sh --mode preview

# Открыть прежнюю исходную сцену (финальную B открывайте командой ниже):
media/sinegor-led/run_blender.sh --open
```

Обёртка находит `blender` в PATH либо установленный `org.blender.Blender` Flatpak.
Для Flatpak рабочая папка должна быть доступна приложению. Не запускайте приложение
от root. Если оболочка сообщает об отсутствии Blender, установите 5.1.1 самостоятельно
или укажите абсолютный путь к имеющемуся Blender в следующей команде.

Прямой запуск из папки `media/sinegor-led`:

```bash
OCIO="$PWD/srgb.ocio" /path/to/blender -b --factory-startup \
  --python-exit-code 1 --python "$PWD/generate.py" -- --mode preview
```

На Windows в PowerShell из этой же папки:

```powershell
$env:OCIO = (Resolve-Path .\srgb.ocio).Path
& 'C:\Program Files\Blender Foundation\Blender 5.1\blender.exe' -b --factory-startup `
  --python-exit-code 1 --python .\generate.py -- --mode preview
# Для открытия сцены с тем же профилем:
& 'C:\Program Files\Blender Foundation\Blender 5.1\blender.exe' .\output\SINEGOR_LAB.blend
```

`--preset original|A|B|C` выбирает свечение. С пресетом папка по умолчанию —
`output/glow_revision/<preset>`; без пресета сохраняются исходные параметры и папка `output`.
`--config /path/to/config.json` задаёт базовую конфигурацию, `--out /path/to/output`
меняет папку результатов. Путь к шрифту считается относительно config.json.
Повторный запуск перезаписывает одноимённые результаты. `.blend` сохраняется до
тестового рендера: в нём активна сцена цикла и установлен кадр 1.

Открытие финального B в установленном Flatpak Blender из корня репозитория:

```bash
SINEGOR_LED_DIR="$PWD/media/sinegor-led"
flatpak run "--env=OCIO=$SINEGOR_LED_DIR/srgb.ocio" org.blender.Blender \
  "$SINEGOR_LED_DIR/output/final_B/SINEGOR_LAB.blend"
```

Для обычной установки используйте `OCIO="$SINEGOR_LED_DIR/srgb.ocio" blender
"$SINEGOR_LED_DIR/output/final_B/SINEGOR_LAB.blend"` в одну строку.

## Цветовой профиль и совместимость

В обнаруженной Fedora Flatpak-сборке Blender 5.1.1 стандартный конфиг OCIO 2.5
не загружается библиотекой OCIO 2.4.2. Включён небольшой собственный `srgb.ocio`
с обычным преобразованием scene-linear Rec.709 → sRGB, без LUT и тонального сжатия.
Обёртка задаёт его через `OCIO` только для запускаемого Blender. Системные настройки
и файлы установленного приложения не изменяются.

Для воспроизводимого цвета всегда используйте этот профиль, включая открытие
`.blend`. Сам профиль не упаковывается в `.blend`. Шрифт, напротив, упакован.
Материалы получают значения HEX после обратного sRGB-преобразования; используются
Standard, exposure 0, gamma 1. Проверка PNG подтвердила точные RGB заданных цветов
на непрозрачных участках лицевых поверхностей.

В коде используются новый `scene.compositing_node_group`, выход группы и реальные
входы узлов Blender 5.1.1. Старые Eevee Bloom, `scene.node_tree`, `CompositorNodeMixRGB`
и устаревшие свойства узлов не используются. Рендер — Cycles CPU, 32 samples,
композитор CPU. Сцена не содержит подложки или декоративных объектов.

## Параметры

Измените `config.json`, затем снова запустите preview. `generate.py` создаёт сцену
заново, поэтому ручные изменения `.blend` при перегенерации не сохранятся.
Для сохранения ручной версии используйте другое имя файла/папку результатов.

| Параметр | Назначение |
| --- | --- |
| `sinegor_color`, `lab_color` | HEX-цвета, исходно `#F1F4F2`, `#9DE0C4` |
| `text_width_fraction` | Ширина надписи относительно кадра, исходно 0.82 |
| `tracking` | Межбуквенный интервал |
| `camera_width` | Ширина ортографического кадра в единицах сцены |
| `font_size` | Базовый размер кривой; итоговая ширина автоматически подгоняется по `text_width_fraction` |
| `depth`, `bevel`, `bevel_resolution` | Экструзия, радиус и гладкость фаски до подгонки масштаба |
| `face_strength`, `edge_brightness` | Яркость лицевой поверхности и фаски |
| `glow_near_px`, `glow_far_px` | Размеры двух Gaussian Blur в пикселях при полном разрешении |
| `glow_near_opacity`, `glow_far_opacity` | Плотность ближнего и дальнего ореола |
| `glow_intensity` | Общая интенсивность ореола |
| `loop_amplitude` | Амплитуда изменения ореола: 0.04 означает ±4%; допустимо 0…0.05 |
| `intro_frames`, `loop_frames`, `fps` | Длина и частота, исходно 50 / 750 / 25 |
| `width`, `height`, `samples`, `png_depth` | Размер, сэмплы и глубина PNG; 8 или 16 бит |

Сильное увеличение `face_strength` может обесцветить RGB при Standard. После
изменения цветов, размеров или фаски заново проверьте отступы и читаемость.
В интерфейсе Blender доступны обе сцены: `01 — Включение` и `02 — Цикл`.
В каждой один текстовый объект с двумя материалами и неподвижная фронтальная камера.
Ключевые узлы композитинга подписаны; драйверы содержат только встроенные
арифметические выражения Blender, без обработчиков и внешнего Python-кода.

## Как устроены прозрачность и анимация

Ореол формируется двумя размытыми копиями RGBA букв. Для изменения его плотности
изображение переводится из premultiplied в straight, альфа масштабируется,
после чего изображение возвращается в premultiplied. Два ореола и буквы собираются
операцией Alpha Over. Blender сохраняет PNG с обычной straight-альфой.
Так ореол сохраняется за пределами букв при наложении на видео.

Включение — монотонная функция `6t^5 − 15t^4 + 10t^3`, где
`t = clamp((frame − 1) / 49, 0, 1)`. Первый кадр невидим, кадр 50 — рабочее
состояние. Колебаний при включении нет. Длительность клипа — 50/25 = 2 секунды.

Цикл меняет только ореол:
`glow_intensity × (1 + 0.04 × sin(2π × (frame − 1) / 750))`.
Лицевые поверхности и положения букв постоянны. Выгружаются кадры **1…750**,
что при 25 FPS даёт ровно 30 секунд. Виртуальный кадр **751** совпадает с кадром 1
и в финальную последовательность не включается. Последний экспортируемый кадр
не обязан совпадать с первым: между ними должен быть обычный шаг периодической
функции. Производная также непрерывна. Конец включения совпадает с началом цикла.

## Шрифт

`fonts/Manrope-SemiBold.ttf` получен без скачивания из существующего
`apps/web/assets/fonts/Manrope-variable.ttf`: ось `wght` закреплена на **600**.
Лицензия исходного Manrope находится в `fonts/OFL.txt`.

В статической копии объединены пересекающиеся прямолинейные контуры буквы A:
иначе импорт шрифта в Blender оставляет две прорези у перекладины. Очертание
строится по исходным координатам Manrope; пересечения округляются до единицы
TrueType (1/2000 em). Исходный шрифт сайта не изменён. Остальные глифы сохранены.

Повторная подготовка шрифта нужна только при замене исходника:

```bash
python3 media/sinegor-led/prepare_font.py
```

Для этой вспомогательной операции используются имеющиеся в Linux нативные
библиотеки HarfBuzz и HarfBuzz Subset через ctypes. `font_outline.py` выполняет
объединение контуров и пересчёт таблиц/контрольных сумм TTF. Никакие сторонние
Python-пакеты не устанавливаются. На других платформах используйте уже подготовленный
TTF из комплекта; для самого Blender эти библиотеки не нужны.

## Повторный финальный экспорт

B согласован пользователем. Для воспроизведения используйте **новую пустую папку**,
чтобы не перезаписывать результат и не оставлять старые кадры при изменении длины.
Генератор сам не удаляет прежние PNG и не проверяет пустоту папки.

```bash
media/sinegor-led/run_blender.sh --mode final --approved-final --preset B \
  --out media/sinegor-led/output/final_B_new
python3 media/sinegor-led/verify_export.py --out media/sinegor-led/output/final_B_new
```

Без `--approved-final` режим final завершается ошибкой до создания сцены.
Этот флаг предотвращает случайный полный рендер; он не заменяет согласование.
Ожидаемые результаты:

- `<out>/intro/intro_0001.png` … `intro_0050.png`;
- `<out>/loop/loop_0001.png` … `loop_0750.png`.

`verify_export.py` проверяет все 800 файлов, точную нумерацию без лишнего хвоста,
RGBA/размер, прозрачный периметр, неизменность непрозрачных букв, цвета,
монотонное включение, совпадение с согласованными пробными кадрами и непрерывность
стыка относительно соседних шагов, а также все 750 соседних переходов, включая стык.
Для B допустимы не более 2/255 по RGB на имитации графита и 1/255 по альфе
между соседними кадрами с учётом округления. Дополнительно оценивается соответствие ореола
медленной синусоиде. Контроль рассчитан на согласованный B и 8-битную поставку.
GUI-просмотр в исходном проекте Shotcut остаётся отдельной проверкой.
Не добавляйте виртуальный кадр 751 и не создавайте дублирующий завершающий кадр.

## Использование в Shotcut

1. Установите режим проекта **25 FPS** до импорта. Для проверки пиксель в пиксель
   создайте пользовательский режим **2048 × 720**, progressive, square pixels.
   Для итогового видео другого размера сохраняйте 25 FPS и масштабируйте надпись.
2. Откройте `output/final_B/intro/intro_0001.png`, включите **Properties → Image sequence**.
   Убедитесь, что одному PNG соответствует один кадр, а длительность равна 2 секундам.
3. Аналогично откройте `output/final_B/loop/loop_0001.png` как последовательность; длительность —
   30 секунд. Не импортируйте все PNG как независимые фото или слайды.
4. Разместите основное видео на V1, включение и цикл — последовательно на V2.
   Включите обычное композитирование верхней дорожки (Over). Chroma Key не нужен.
5. Для повторения скопируйте клип цикла вплотную за ним, без зазора и перекрытия.
   Не добавляйте dissolve/transition на стык и не меняйте скорость клипа.
6. Просмотрите переход включение → цикл и несколько стыков цикл → цикл на тёмном
   и меняющемся видео. Для размера 683 × 239 используйте точные значения фильтра
   Size, Position & Rotate, если нужен такой размер в итоговом кадре.

Поддержка PNG-альфы и включение Image sequence описаны в
[официальном FAQ Shotcut](https://www.shotcut.org/FAQ/) и
[описании Image Properties](https://forum.shotcut.org/t/image-properties/12924).
Последовательность цикла проверена штатным `qimage` и `qtblend` из установленного
Shotcut без GUI: `output/final_B/checks/loop_twice.mlt` задаёт 1500 кадров,
683 × 239, 25 FPS, два повторения и подложку-имитацию `#171C20`.
Все 1500 кадров диагностического видео декодированы: второй цикл совпадает с первым,
максимальный шаг на стыке 2/255 по RGB и не превышает обычные шаги внутри цикла.
Сводка — `output/final_B/checks/mlt_checks.json`. `ttl=1` задаёт один PNG на кадр,
`begin=1` — начало с 0001; параметры описаны в
[документации MLT qimage](https://www.mltframework.org/plugins/ProducerQimage/).

Диагностический `checks/loop_twice_graphite.mkv` — **непрозрачное** видео с имитацией
графита, предназначенное только для проверки. Для наложения используйте PNG RGBA.
Дополнительные видеофайлы с альфа-каналом не создавались. GUI и исходный проект
Shotcut не открывались и не менялись; оценка результата на исходном движущемся
видео в этом этапе не выполнялась.
