# Одноразовый доступ для подключения Метрики

Подключение счётчика 114298562 и пересоздание только frontend разрешены поручением владельца. Повторное согласование этих действий не требуется. Нужен новый sudo-доступ: пользователь SSH не имеет доступа к Docker без sudo; старые каналы закрыты.

Он меняет только `YANDEX_METRIKA_ENABLED=false` → `true` и пустой `YANDEX_METRIKA_ID` → `114298562` в действующем private/compose.env. Только web пересоздаётся, без сборки и скачивания образов. Остальные четыре контейнера, код, Git, кабинет Метрики и цели не меняются. Публичные страницы могут быть кратко недоступны при пересоздании frontend.

До изменения проверяются регрессия, исходный образ и семантический diff Compose. Исходные значения сохраняются в памяти; другие строки env, права и владелец сохраняются. При ошибке, отрицательных браузерных проверках или отсутствии решения в течение 45 минут сценарий возвращает исходные параметры и пересоздаёт только web. После положительных проверок счётчик остаётся включённым.

Выполните на **локальном компьютере Fedora** в терминале:

```bash
sinegor_metrika_access_dir=$(mktemp -d /tmp/sinegor-sudo.XXXXXX)
chmod 700 "$sinegor_metrika_access_dir"
mkfifo -m 600 "$sinegor_metrika_access_dir/password.fifo"
printf 'Передайте агенту только путь: %s/password.fifo\n' "$sinegor_metrika_access_dir"
IFS= read -r -s -p 'Пароль sudo VPS для подключения Метрики: ' sinegor_metrika_password
printf '\n'
printf '%s\n' "$sinegor_metrika_password" > "$sinegor_metrika_access_dir/password.fifo"
unset sinegor_metrika_password
```

Передайте **только путь** `/tmp/sinegor-sudo.…/password.fifo`, оставив терминал открытым. Сам пароль в чат не передавайте. Запись в FIFO ожидает чтения агентом — это нормальное поведение. Пароль поступает напрямую в stdin SSH/sudo, без сохранения и вывода. Перед чтением канала проверяются SSH и хеш сценария. После завершения канал удаляется.
